# 0.8.0 feature implementation record

Audited September 5, 2026, against commit `df69702` and extension version `0.7.1`; work packages A–N are implemented in version 0.8.0 within the supported scope documented below. This record summarizes the completed work; remaining candidates are tracked in [ROADMAP.md](../ROADMAP.md).

## Implementation status: language analysis and source edits

The tables below describe the implemented behavior and its validation limits.

| Package | Implemented behavior | Deliberate limits and validation |
| --- | --- | --- |
| A | A cached syntax model now drives the workspace index, outline, definitions, references, hover, completion, and user-procedure signatures. Namespace names remain case-sensitive; static imports/paths and canonical variable bindings connect reopened namespaces and files. The index handles readiness, document versions, changes, deletion, exclusions, and cancellation. | Dynamically generated definitions, unresolved frame aliases, and ambiguous receivers stay unresolved. Static import patterns support the common `*` and `?` forms; arbitrary Tcl evaluation is never used for analysis. Provider regressions cover exact ranges, multiline/default parameters, Unicode, namespace resolution, literals, and updated document versions. |
| B | Variable extraction/inlining, namespace extraction/rename, and lint fixes build edits from syntax/binding ranges. Namespace operations preserve static imported helpers, cross-file callers, wildcard imports, path lists, relative qualified variables, and multiline data; collisions and affected opaque callbacks are rejected. Inlining rejects conditional assignments and unknown calls that could mutate the caller. | Extraction to a namespace accepts complete, unqualified top-level procedures. Variable inlining is intentionally limited to a single literal assignment with proven source-order/frame constraints. Unknown dynamic namespace directives and unsupported transformations return a reason without applying edits. Real Tcl execution comparisons cover the supported transformations, including cross-file namespace imports and paths. |
| J | Configurable reference CodeLens uses the versioned occurrence cache and opens VS Code references. Run/Debug test lenses use the Test Explorer's test identities and execution commands. | Counts cover statically resolved calls; constructors/destructors do not receive misleading explicit-call counts. Provider tests check literal exclusion and cross-file count refresh. |
| K | Static classes, methods, constructors/destructors, object variables, and literal lambdas have declarations/scopes. Named instances and literal `set object [Class new]` bindings support method navigation/completion, inherited methods, and constructor signatures. Class/method rename checks collisions and preserves qualification, including `oo::define` and superclass references. | Generated classes, arbitrary factory-returned receivers, conflicting instance assignments, mixin dispatch, and ambiguous inheritance remain outside static resolution. Editor tests run on every supported Tcl version; TclOO execution-equivalence checks require an interpreter providing `oo::class`. |

**Focused verification:** The real VS Code extension host passed the language, source-edit, and namespace safety suites together (26 tests). The namespace suite includes five before/after or rejection regressions for imports, paths, qualified variables, collisions, and callbacks. Compilation and lint also pass; broader integration validation is recorded separately below.

## Implementation status: runtime workflows and verification

| Package | Implemented behavior | Validation and scope |
| --- | --- | --- |
| C | Selection formatting uses enclosing script context, preserves base indentation/newline style and literal bytes, and formats list-form switch patterns/bodies. | Complete commands only; partial words and literal selections are left unchanged. Tests check CRLF, multiline literal values, idempotence, and before/after Tcl execution. |
| D | Stack frames and variable handles carry frame/scope/array identities through inspection, evaluation, and editing. Resume invalidates prior handles. | Nested caller/callee/global/array fixtures verify exact targets and stale-reference errors. |
| E | Test Explorer Run, Debug, and Coverage share discovery, selection/exclusion, execution status, and owned-process cancellation. Debug uses original source breakpoints; native coverage and editor/export totals share parsed reports. | Real VS Code tests cover all profiles, failures, concurrent coverage isolation, cancellation/restart, missing files, and stale discovery. Coverage counts executable source lines using command traces; it is not branch coverage. |
| F | Native Tcl task schema, activation, lazy task provider, install service, and source problem matcher are contributed. Saved labels, grouping, presentation, environment, and arguments survive resolution. | A fresh two-folder host resolves and executes a saved task in the second folder and publishes its error at the original source line. Missing test runners are not offered. |
| G | Shared interpreter/cwd resolution supports operation overrides, explicit feature settings, per-folder general settings, and defaults. Run arguments/environment can be saved; REPL startup is serialized and recovers after close/context changes. | Two-folder configuration tests verify override precedence and isolation. Process arguments include empty strings, spaces, Unicode, and metacharacters; cancelled saves abort launch. |
| H | Package catalogs honor automatic-discovery settings and feed completion. Static requirements retain exact/range semantics, all locations, unknowns, conflicts, and compatible update candidates. Local installation validates loadability and preserves existing files. | Native Tcl version tests and temporary package installs pass. Existing teacup integration is retained; a live external teacup registry was not exercised. |
| I | Structural diagnostics publish immediately; interpreter checks debounce, cancel, and cache unavailable interpreters. Parsed lint rules support individual severities and next-line suppression comments. | Rapid supersession and close cleanup settle pending work. Literal command text does not warn; diagnostics never execute user code. |
| L | Protocol v1 authenticates loopback attach, maps remote source prefixes, times out failed connections, and detaches without killing an external process. | Independent real-server fixtures cover authentication, mapping, reconnect, and ownership. Remote use is through an SSH tunnel; arbitrary-process injection and direct remote sockets are outside scope. |
| M | Opt-in launch `debugThreads` discovers new `thread::create` workers and routes stacks, inspection, pause/step/continue, and exit events by stable thread identity. | Two workers step and expose variables independently. Literal worker bodies map to original lines. Attach-mode worker discovery and preexisting pools remain unsupported; dynamically generated worker source may appear as generated files. |
| N | Project/package scaffolds substitute name, namespace, and version; both creation flows protect occupied destinations. Generated package indexes and applicable build/test entry points agree. | Temporary named package fixtures load at the requested version, build, run tests, and reject overwrites. |
| M0 | Standalone and focused test runners, pinned VS Code integration with an isolated two-folder workspace, and Linux/macOS/Windows CI are added. Manifest registrations, packaging contents, and user/developer docs are reconciled. | Local verification is recorded below. CI has been configured but has not been run on remote runners. |

**Integrated verification (September 5, 2026):** Compilation and lint pass. The final VS Code 1.136.1 extension-host run passes **185 tests**, including the five namespace regressions, native tasks in a two-folder workspace, selected test debugging/coverage/cancellation, authenticated attach, and Thread workers. The standalone runner passes **101 tests**; these overlap with the full host suite. Local runtime fixtures use macOS, Tcl 8.5.9, and Thread 2.6.6. TclOO structural provider tests run locally; TclOO execution comparisons need a newer interpreter with `oo::class`. Package-file inspection confirms runtime modules and the Tcl server are included and test/CI files are excluded. The CRLF-aware diff check passes. Remote CI runners and live teacup sources remain unverified.

**Insiders UI verification:** Computer Use exercised the development extension in VS Code Insiders 1.137.0 using the supplied `tcl_testcode` samples. All 12 sample tests pass. Selected Run/Debug/Coverage, original-source breakpoints and stepping, procedure signatures/definitions/reference CodeLens, TclOO navigation, formatting, numeric-expression quick fixes, and REPL restart were verified. The pass found and fixed native editor breakpoint registration, duplicate scalar-assignment stops, stop reasons, and test/coverage status/output defects. See [INSIDERS_UI_TEST_REPORT.md](INSIDERS_UI_TEST_REPORT.md) for steps, observations, and scope.

## Release delivery

The GitHub Actions release workflow accepts stable version tags reachable from `main`, validates tag/package/lock/changelog agreement, runs the reusable three-platform checks, and publishes the tagged VSIX with its changelog notes to GitHub Releases. Branch checks continue on pushes and pull requests. Release guard tests use temporary Git histories; no release tag is created by local validation.
